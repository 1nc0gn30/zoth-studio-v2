## 4. Prioritized Remediation Blueprint (`v2` Backlog)

### P0 — Critical Security, Subprocess Safety & Crash Elimination (Blockers)
1. **Strict Loopback CORS & `Host` Allowlist (`agy_hermes_proxy.py`)**:
   - Replace `allow_origins=["*"]` + `allow_credentials=True` with strict loopback origin validation (exact scheme + host in `{localhost, 127.0.0.1, [::1]}` with validated numeric port, `allow_credentials=False`, rejecting `https://example.invalid` and port-suffix spoofs like `http://127.0.0.1:18000.example.invalid` with `403` and emitting `Vary: Origin`).
   - Enforce a strict `Host` header allowlist middleware (`127.0.0.1`, `localhost`, `[::1]` with optional numeric port) returning `400`/`403` JSON on `Host: evil.example:*` to block DNS rebinding.
   - Optional local bearer token (`AGY_PROXY_TOKEN` env var, opt-in so existing loopback clients keep working by default while enabling authenticated mode).
2. **Pydantic Request Validation, OpenAI Error Envelopes & `MAX_BODY_BYTES` Cap**:
   - Define strict Pydantic models (`ChatCompletionRequest`, `ChatMessage`, `ApiShowRequest`) and global exception handlers returning OpenAI-formatted `{"error": {"message", "type", "param", "code"}}` JSON (`400`/`413`/`422`) — zero plain-text `500` crashes.
   - Enforce a configurable `MAX_BODY_BYTES` cap (e.g., `4 MiB`) rejecting oversized bodies with `413 Payload Too Large` JSON before parsing.
3. **Subprocess Lifecycle Governance (Orphan Cleanup, Semaphore, Timeout, Large Buffer, Non-Zero Exit Handling)**:
   - Wrap both streaming and non-streaming subprocess lifecycles in `try ... finally:` blocks that `terminate()` → wait `2s` → `kill()` + `wait()` on `asyncio.CancelledError`, timeout, or client disconnect (`request.is_disconnected()`), eliminating orphan `agy` processes.
   - Guard execution with an `asyncio.Semaphore` (`AGY_PROXY_MAX_CONCURRENCY`, default `4`, returning `429 Too Many Requests` / `503` on saturation) and per-request timeout (`AGY_PROXY_TIMEOUT_SECONDS`, default `180`, passing `--print-timeout` + `asyncio.wait_for`), returning `504 Gateway Timeout` OpenAI JSON error on timeout.
   - Set `limit=8 * 1024 * 1024` (`8 MiB`) on `create_subprocess_exec` streams so large JSON event lines never trigger `LimitOverrunError`.
   - Always capture `stderr` and check `proc.returncode != 0`: return `502 Bad Gateway` OpenAI JSON error (non-streaming) or an explicit SSE error event + `data: [DONE]` (streaming) instead of silent `200 OK` empty replies or `0 B` streams.
