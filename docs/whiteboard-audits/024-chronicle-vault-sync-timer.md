## 3. 5-Level Deep Findings (`file:line`)

### L1 — Systemd Unit Security, Reliability, Portability & Chroot Packaging
1. **CRITICAL: Complete absence from ZothOS Live ISO chroot (`~/NullAITech/zoth-os/config/includes.chroot/etc/systemd/user/`, P0).** Neither `chronicle-vault-sync.timer`, `chronicle-vault-sync.service`, `chronicle-vault.service`, nor `timers.target.wants/chronicle-vault-sync.timer` exist in `zoth-os` chroot (`timers.target.wants/` directory does not exist at all). While `zoth-os` packages `/usr/local/bin/zoth-memory-vault` (wrapper checking `/opt/zoth-memory-vault/cli.py` and `$HOME/NullAITech/zoth-memory-vault/cli.py`), a freshly booted ZothOS ISO will never run background Chronicle Vault syncs.
2. **CRITICAL: Hardcoded user home directory in live unit (`~/.config/systemd/user/chronicle-vault-sync.service:5-6`, P0).** `WorkingDirectory=` and `ExecStart=/usr/bin/python3 .../hermes_hook.py --hours 24` hardcode the literal host user directory rather than using systemd `%h` specifiers or `/usr/local/bin/zoth-memory-vault sync-recent --hours 24`, breaking multi-user and ISO portability.
3. **Zero security sandboxing, resource bounds, or timeout (`~/.config/systemd/user/chronicle-vault-sync.service:4-7`, P1).** Unlike peer ZothOS user units (`certpath-roadmap-studio.service`, `agy-hermes-proxy.service`), `chronicle-vault-sync.service` sets only `Nice=15` and omits `NoNewPrivileges=yes`, `PrivateTmp=yes`, `ProtectSystem=strict` (with `ReadWritePaths=%h/NullAITech/zoth-memory-vault/data`), `MemoryMax=512M`, `CPUQuota=100%`, `TimeoutStartSec=120`, `IOSchedulingClass=idle`, `ConditionPathExists=`, `Documentation=`, and `SyslogIdentifier=chronicle-vault-sync`. With `TimeoutStartUSec=infinity` and `MemoryMax=infinity`, a hung SQLite lock or runaway file stalls all subsequent timer triggers forever and already peaks at `470–486.5M` RAM.
4. **Zero cross-process overlap locking (`chronicle-vault-sync.service:6`; `server.py:37,642`, P1).** `server.py` uses an in-process `threading.Lock()` (`SYNC_LOCK`) that does not synchronize against `chronicle-vault-sync.service` or manual `zoth-memory-vault sync` invocations. Running `POST :8161/api/sync` concurrently with a 30-minute timer tick causes uncoordinated SQLite write contention and duplicate full FTS5 rebuilds.
5. **World-readable vault database permissions (`~/NullAITech/zoth-memory-vault/data/memory_vault.db`, P1).** File mode is `0644` (`-rw-r--r--`); `db.get_conn()` (`db.py:47-59`) never enforces `0700` on `DATA_DIR` or `0600` on `DB_PATH` (`-wal`/`-shm`), leaving all consolidated Hermes/AGY transcripts and unredacted secrets readable by any local OS account.
